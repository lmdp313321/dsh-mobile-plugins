# dsh-mobile-plugins

**手机端专属的 DeepSeek Harness 插件市场。**

PC 端有 26,000+ 插件，但手机端能直接用的大多是碰运气。这个仓库只做一件事：
把真正高频、刚需的插件**按手机重新做一遍**——不是移植，是按小屏、触控、移动场景重新设计。

## 为什么需要这个仓库

DSH 官方壳（dsh-mobile-apk）作者自己写过警示：

> 内置市场牵涉大量第三方插件，**绝大多数插件在手机端不一定可用、大概率有 bug**
> （移动端与桌面端在 WebView 内核/文件系统/权限模型/运行环境差异大）

差异不是"样式没适配"，而是真实的能力边界不同：

| 维度 | PC | 手机 |
|---|---|---|
| 屏幕 | 大屏多窗 | 窄屏单手 |
| 输入 | 键盘鼠标 | 触控、语音、拍照 |
| 后台 | 一直开着 | 随时被系统杀 |
| 通知 | 不必要 | **必需**（切走了怎么知道跑完） |
| 文件 | 拖拽即用 | 相册/分享/SAF |
| 网络 | 稳定 | 常切 4G/WiFi |

所以"改造"不等于改 CSS。真正值得做的是**只有手机上才成立**的能力。

## 已完成

### 1. 手机语音朗读（dsh-mobile-tts）

让 AI 的回复可以被**朗读出来**。

**为什么手机独有**：PC 上你盯着屏幕看就够了；手机上你走路、做饭、躺着时，听比看方便。

**技术基础**：Android 壳桥里 `ttsSpeak` / `ttsVoices` / `ttsStop` 三个接口**早就存在且可用**，
但目前全仓没有任何 UI 调用点——它只被当成 Web Speech API 的 polyfill 垫片用，
普通用户根本摸不到。这个插件把那层垫片接出来，做成真实按钮。

**功能**：
- 每条 AI 回复下方加「朗读」按钮
- 可调语速 / 音高 / 音色
- 长文自动分段朗读，支持暂停/继续/停止
- 朗读时高亮当前段落

安装：

```bash
dsh plugin --profile web add lmdp313321/dsh-mobile-plugins/tts
```

## 不做什么

明确排除，避免浪费：

- ❌ **移植 dsh-TUI**：手机上没终端场景
- ❌ **移植 DSH Desktop**：手机本身就是壳
- ❌ **重做 AI 浏览器**：壳侧已有 19 个工具，很完整
- ❌ **重做手机控制**：壳侧已有 14 个工具
- ❌ **重做拍照看图**：壳侧 `camera` 来件通道已铺好，拍照直接进会话

## 开发约定

每个插件是独立目录，结构统一：

```
<plugin>/
├── package.json        # dsh.client 声明 + exports
├── cordis.patch.yml    # 安装到 profile 的 patch 行
├── index.js            # Host 半边
├── client.js           # Client 半边（React）
├── locale/{zh,en}.json # 显示元数据
├── icon.svg            # 图标
└── README.md
```

三条硬规则：

1. **只用主题 token**（`--dsw-alias-*`），不写死颜色——跟随宿主深色/浅色
2. **不 import Harness Client 包**，控件自己写——避免上游变更打崩
3. **桥能力必须做特性检测**，`androidBridge.version` 存在才用，PC 上优雅降级
